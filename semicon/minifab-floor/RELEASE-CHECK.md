## Provenance of the verbatim copies

`ORIGINALS.sha256` lists the 17 copied files by their path *in this
directory*, so `cd semicon/minifab-floor && sha256sum -c ORIGINALS.sha256`
checks them. `recheck.sh` leg 0 runs that check and also fails if any file
under `originals/` is unlisted. Each hash is the archive original's: the
files are byte-identical copies. The `originals/maitria/...` files come from
the archive's MAITRIA receipts tree. The `lean/...` files come from the
archive's bernstein-logic `lean-aux` Lean package, and its `lean-aux/`
prefix maps to `lean/` here.

Because the copies are verbatim, their own text still carries
archive-internal vocabulary:
* archive-relative paths of unshipped notes (e.g. a `hearth/...` prefix, in
  the docstrings and in the four mutant patches' `a/…` headers);
* workstream labels (`W408`, `W666`, `W668`, `W676`);
* dated design rulings attributed to davidad (`DeterministicCollapse.lean`,
  `Basic.lean`, `Selection.lean`).

None of this is personal or confidential. It is kept so that the hashes stay
the archive's. One vendored docstring sentence is known to be false, and
`lean/IDT/FloorContiguity.ERRATUM.md` supersedes it explicitly, without
editing the file.

## Genuine limitations (kept, not release blockers)

* Receipt status per revision is tabulated at the top of `README.md`.
  `receipts/provenance.jsonl` records which run produced each receipt.
* The two-sided result covers **N ≤ 7 only**.
  * The lower side is decided on model R + queue order: by z3 for N ≤ 7 and
    by CNF + LRAT/DRAT, for N ≤ 7. Its trust base
    is cake_lpr, the encoder, and two pen-and-paper arguments: R ⊇ net and
    the queue-order exchange lemma. Without the reduction (no exchange
    lemma needed) it is certified for N ≤ 5.
  * The upper side is a net replay of π\*, instance-adapted to N lots.
* For N = 8..12 only the upper side is shipped (π\* replay). No lower bound
  is shipped for N ≥ 8.
* The Lean floor (255N + 375, N ≥ 4) is a theorem about `MFSchedule`. The net
  does not project onto `MFSchedule` because of two moves: the same-round
  fresh-token tick and the same-round machine handover (README, Findings 2).
  So the Lean floor is **not** a proof for the net at N ≥ 8.
* The replays decode the sealed part of the `.glc` containers. The rest of
  the net is a named transcribed remainder, and so is the round semantics
  (README, "What this does and does not establish"). The container does not
  seal it, and mtk cannot be built from public sources.
* Every makespan here is the round of the N-th arrival into q6, **not** the
  round at which all lots have shipped.
* The qtsl book's own worked-example chapter (in the qtsl repository) still
  carries the pre-erratum wording. This repository's chapter is corrected.
