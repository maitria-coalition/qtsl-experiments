## Process catch, banked for a successor: rechecks rewrite committed receipts

The incumbent-lane recheck drivers (gymnasium run_checks/run_tt_checks,
supermartingales recheck) refresh the committed receipt JSONs in place
on every run — so a mere verification run on a loaded machine rewrites
published check-median cells (this pass's own `make chapter` did
exactly that: one gym-table cell drifted 1.1 ms -> 1.9 ms and was
caught at commit review; receipts restored, table re-derived from the
committed bytes). The sealed-container lanes already route timing
receipts out of tree by default with an explicit publish switch
(receipts/TIMINGS-PATH-NOTE.md); the incumbent lanes deserve the same
fix, and it belongs to the re-measurement leg that owns timing cells.
